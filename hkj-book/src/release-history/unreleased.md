# Unreleased: 0.5.0

_Not released yet: these changes are on `main`, and the `latest` book describes them._

To try them, depend on `0.5.0-SNAPSHOT` from the snapshots repository, as [Gradle SNAPSHOT Configuration](../tooling/manual_setup.md#gradle-snapshot-configuration) shows.

~~~admonish info title="At a glance"
- **Navigators are on by default, and a navigator is a path**: `UserFocus.address().street()` and `OrderFocus.lines().quantity()` work with a bare `@GenerateFocus`, and the navigator goes wherever a path goes.
- **Optics over a nullable field pass a nullness checker**: every optic and Focus path type takes a `@Nullable` focus, as does each bridge into an Effect Path that says what a null focus becomes.
- **`@PathSource` has a page of its own**, beside `GenericPath` in the Effect Path chapter.
- **`StateT` is built from its state function alone**, and `mapT` takes only the transformation, as on every other transformer.
- **A `Right` or a `Success` always holds a value**: `Either`, `Try` and their Paths refuse null as a success, as `Validated` and `EitherOrBoth` do, and `Unit` stands for a step with nothing to return.
- **A `Left` always holds an error**: the core `Either` and `EitherT` refuse a null error, as every Effect Path already did.
- **A lazy computation always gives a value**: `IO`, `VTask`, `VStream`, `State`, `Lazy` and the other lazy types, and every Path over them, refuse a null value, as `Either` and `Try` do. Only `Id` keeps one, for the optics.
~~~

## Mapping {#mapping}

- **A misspelt `@MapKey` value suggests the component's bare name** ([#1112](https://github.com/higher-kinded-j/higher-kinded-j/issues/1112)). The hint now offers `byOwner` rather than `byOwner()`, so it can be used as the annotation's value. Hints that name methods keep their parentheses.
- **A generic spec over an array of its parameter no longer breaks on a primitive array** ([#1091](https://github.com/higher-kinded-j/higher-kinded-j/issues/1091)). No type argument is a primitive, so a spec over `Page<T[]>` no longer covers a `Page<int[]>` field, which crashed the processor or failed in generated code. The field reports no usable source instead. See [The boundaries of a generic spec](../mapping/rules.md#generic-boundaries).
- **A bounded generic spec no longer covers an argument outside its bound** ([#1118](https://github.com/higher-kinded-j/higher-kinded-j/issues/1118)). A spec over `Page<T>` with `T extends Number` covered a `Page<String>` field and broke the generated code. That field now reports no usable source, naming the bound, or nests through a spec for `Page<String>` declared beside it. See [A bounded spec covers only what its bounds admit](../mapping/rules.md#generic-spec-bounds).
- **An element-mapped spec nests where a type argument passes through unconverted** ([#1122](https://github.com/higher-kinded-j/higher-kinded-j/issues/1122)). A spec over `TaggedPage<T, X>` whose leaf converts only the elements broke the generated code wherever it nested, since no leaf names `X`. The generated call now spells out its type arguments, keeping a `@Nullable` the domain or wire record declares. See [How an element-mapped spec nests](../mapping/rules.md#element-mapped-nesting).
- **A merge fills a component through a generic spec** ([#1123](https://github.com/higher-kinded-j/higher-kinded-j/issues/1123)). A threaded spec such as `PageMapping<T>` now fills a merge as it nests in a mapping. An element-mapped spec is not supported yet, and the merge says so, offering the leaf that builds it. See [How a merge fills](../mapping/rules.md#how-a-merge-fills).
- **The most specific of several specs for a pair maps it** ([#1123](https://github.com/higher-kinded-j/higher-kinded-j/issues/1123)). `TagPageMapping` beside `PageMapping<T>`, or `PageMapping<T>` beside `CodecPageMapping<T, TDto>`, made a field ambiguous. The more specific now maps it, and a compiler note names a dependency's spec it displaced. See [The most specific spec for a pair is used](../mapping/rules.md#generic-spec-precedence).
- **The processor names what an accessor-style leaf or marker meant** ([#907](https://github.com/higher-kinded-j/higher-kinded-j/issues/907)): a leaf written `getEmail()` for the component `email` now draws `Did you mean 'email()'?`, as a near misspelling already did. An `@Unmapped` or `@ReadOnly` marker named after its accessor, `setStamp()` or `getId()`, draws the property the same way. See [Compiler Messages](../mapping/compiler_errors.md#leaf-names-no-component).
- **More Lombok `@Singular` collections map** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)). A build-only collection whose name has a capital second letter, such as `eMails`, is written whole, whichever capitalisation Lombok gives its clear method. So is one of an unbounded wildcard, or a Guava `ImmutableTable`. An `Iterable` property without type arguments is no longer taken for one. See [A Lombok `@Singular` collection](../mapping/rules.md#singular-collections).
- **A method that only starts like an accessor is never read as one** ([#1128](https://github.com/higher-kinded-j/higher-kinded-j/issues/1128)). A name that runs on in lower case after its `get`, `is` or `set` prefix is a word, while `geteMail()` stays the JavaBeans getter of `eMail`. So `getaway()` no longer reads `away`, and a builder's `settings(String)` writes `settings`. See [How a bean is read and written](../mapping/rules.md#how-a-bean-is-read-and-written).
- **A builder with both `name(...)` and `setName(...)` maps** ([#1128](https://github.com/higher-kinded-j/higher-kinded-j/issues/1128)): the two were taken for rival overloads, which javac never weighs against each other, and the property was refused. `name(...)` writes it. See [How a bean is read and written](../mapping/rules.md#how-a-bean-is-read-and-written).
- **A word a component needs is refused** ([#1128](https://github.com/higher-kinded-j/higher-kinded-j/issues/1128)): a bean's `getx()` and `setx(int)`, with no accessor of `x` beside them, which earlier versions read as `x`. The error offers `getX()` and `setX(int)`, or an `@Unmapped` marker. See [A method that only starts like an accessor](../mapping/rules.md#word-accessors).

## Optics {#optics}

- **`includeFields` offers followable fixes for wildcard containers** ([#1201](https://github.com/higher-kinded-j/higher-kinded-j/issues/1201)). The warning explains the concrete type and widening a container needs, and suggests only one replacement per list. See [Compiler Messages](../optics/compiler_errors.md#generatefocus-includefields-no-navigator).
- **`@GenerateFocus` generates navigators by default, and a navigator is a path** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033)). `UserFocus.address().street()` works on a bare annotation, and `generateNavigators = false` turns navigators off. A navigator can be held as a `FocusPath` or passed to an Effect Path's `focus`, and every path method works on it. See [Fluent navigation with generated navigators](../optics/focus_navigation.md#fluent-navigation-with-generated-navigators).
- **A navigator steps into a container only where the record widens it** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033)). A `Map`, an array or a third-party collection of `@GenerateFocus` records gets a navigator under `widenCollections = true`, or when the new `widenFields` names the field. So turning navigators on never changes what a field's method focuses on. See [The `ZERO_OR_MORE` Asymmetry](../optics/focus_containers.md#the-zero_or_more-asymmetry-and-widencollections).
- **`OrderFocus.lines().quantity()` chains with no `.via(...)`** ([#1103](https://github.com/higher-kinded-j/higher-kinded-j/issues/1103)). A `List`, `Set`, `Collection`, `Optional` or `Maybe` of records gets a navigator, and so does one nested in another, such as `List<Optional<LineItem>>`, or a `Kind` the processor traverses. The navigator is the path the method returned before, so code that declares that path type still compiles. See [Which fields get a navigator](../optics/focus_navigation.md#which-fields-get-a-navigator).
- **`OrderHistoryFocus.orders().customer().email()` keeps navigating after a hop that widens the path** ([#1214](https://github.com/higher-kinded-j/higher-kinded-j/issues/1214)). Each navigator nests a form for each wider path type, `AffineForm` and `TraversalForm`, and a widening hop into a record field returns it instead of the plain path. A record that writes `generateNavigators = true` is told when a form is left out. See [Which fields get a navigator](../optics/focus_navigation.md#which-fields-get-a-navigator).
- **A navigator never reaches a field named like a path method** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033)). A record that writes `generateNavigators = true` is refused when its field reaches a record with a field such as `last`, since `name().last()` would call `FocusPath.last()`. A record on the default keeps that field's plain path, with a note. See [A field named like a path method](../optics/focus_navigation.md#a-field-named-like-a-path-method).
- **A field named `get`, `set` or `count` gets a navigation method** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033)): a navigator skipped it, with a note, because its own method had that name. See [A field named like a path method](../optics/focus_navigation.md#a-field-named-like-a-path-method).
- **`@GenerateFocus` checks the names in `includeFields`, `excludeFields` and `widenFields`** ([#1104](https://github.com/higher-kinded-j/higher-kinded-j/issues/1104)). A name that matches no component is an error at the value, offering the component meant, such as `positions` for `"postions"` or `"Positions"`. A list the record never reads warns, as does a `widenFields` name whose field cannot widen. See [Compiler Messages](../optics/compiler_errors.md#generatefocus-field-list-unknown-name).
- **A `@GenerateFocus` setting that names a constant javac cannot resolve leaves only javac's error** ([#1104](https://github.com/higher-kinded-j/higher-kinded-j/issues/1104)), such as `includeFields = Names.MISSING`. The processor stopped with an exception, which hid that error.
- **The processor suggests methods spelt the way each copy strategy calls them** ([#907](https://github.com/higher-kinded-j/higher-kinded-j/issues/907)). A getter written `name` against a bean's `getName()` now draws `Did you mean 'getName'?`, as a near misspelling already did, and `getActive` draws `'isActive'`. A setter or wither is offered in the convention its strategy needs: a builder's `setName` or `name`, a bean's `setName`, `@Wither`'s `withName`. See [Compiler Messages](../optics/compiler_errors.md#-has-no-method--for-the-generated-lens-to-read-the-value-it-focuses).
- **`@ViaBuilder` rebuilds through Lombok's `@SuperBuilder(toBuilder = true)`** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)). Its `toBuilder()` hands back a builder typed with wildcards, `PetBuilder<?, ?>`, whose setter and `build()` the processor now follows as javac does. A hand-written builder handed back with wildcards works too where a step returns one of its own type parameters, as a self-typed setter or a `C build()` does. See [Non-Standard Naming](../optics/copy_strategies.md#non-standard-naming).
- **More `@ViaBuilder` chains are checked at the spec** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)). A spec over `Node<?>` whose `toBuilder()` returns a type parameter of `Node` builds. A builder bounded by more than one type is checked too, and a chain that cannot compile is refused at the spec rather than in the generated file. See [the chain the lens rebuilds through](../optics/compiler_errors.md#viabuilder-the-chain-the-lens-rebuilds-through).
- **A `@Wither` that returns its class's own type parameter works on a source written with a wildcard** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)): `S withName(String)` on a `Shape<S extends Shape<S>>` rebuilds a `Shape<?>`. See [Copy Strategies](../optics/copy_strategies.md#wither-types-with-withx-methods).
- **A `@ViaBuilder` lens over a Lombok `@Singular` collection replaces it** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)). The collection's setter adds to what `toBuilder()` copied, so for a `@Singular List<String> tags` the generated lens calls the `clearTags()` Lombok writes beside it first, and the lens laws hold. Both `@Builder` and `@SuperBuilder` collections are covered, with or without a `setterPrefix` of lower-case letters such as `with`. See [Non-Standard Naming](../optics/copy_strategies.md#non-standard-naming).
- **A spec's diagnostics never offer a deprecated method** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)). Following one failed a build under `-Werror` in the generated file. A lens named after a protobuf repeated or map field is offered `getTagsList()` or `getPointsMap()`, and a map field's lens is no longer offered the deprecated `getPoints()`. See [the missing accessor](../optics/compiler_errors.md#-has-no-method--for-the-generated-lens-to-read-the-value-it-focuses).
- **A `@ViaBuilder` lens through a protobuf-java message's `addAllTags` or `putAllPoints` replaces the field** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)). Both add to what `toBuilder()` copied, so the generated lens first calls the `clearTags()` or `clearPoints()` protobuf writes beside them, an open enum's `addAllKindsValue` included. See [Non-Standard Naming](../optics/copy_strategies.md#non-standard-naming).
- **`@GenerateFocus` reports a `TraversableGenerator` priority tie once, however many navigators reach the component** ([#1081](https://github.com/higher-kinded-j/higher-kinded-j/issues/1081)): the warning lands on the component that reaches the tied type. It used to repeat for each navigator that walked into the component, the declaring record's own included. See [Compiler Messages](../optics/compiler_errors.md#multiple-traversablegenerator-spi-providers-with-equal-priority-n-support-type-x-a-warning).
- **Any two of `Iso`, `Lens`, `Prism`, `Affine` and `Traversal` compose directly with `andThen`** ([#1021](https://github.com/higher-kinded-j/higher-kinded-j/pull/1021)). An `Iso` followed by a `Traversal` now returns a `Traversal`, and so does a `Traversal` followed by an `Affine` or an `Iso`, with no `asTraversal()` first. The composition table is read from the overloads, so it always matches the library. See [Composition Rules Table](../optics/composition_rules.md#composition-rules-table).
- **A map written through an optic keeps its source's order** ([#1022](https://github.com/higher-kinded-j/higher-kinded-j/pull/1022)): every optic that writes a `Map`, from `Traversals.forMapValues` to `AtInstances.mapAt` and `Setter.forMapValues`, hands back a map in the source's iteration order. An updated key keeps its place and a new key goes at the end. See [Persistent and Third-Party Maps](../optics/common_data_structure_traversals.md#persistent-and-third-party-maps-formapvaluescollecting).
- **`modifyWhen` and `branch` on a `Traversal` call only the function their predicate picks** ([#1026](https://github.com/higher-kinded-j/higher-kinded-j/pull/1026)). Each element is now tested first, so a function may assume the condition that guards it, and an expensive one runs only where it is needed. `Lens.modifyWhen`, `modifyBranch` and `setIf` test first too. See [Complete, Runnable Example](../optics/composing_optics.md#complete-runnable-example).
- **`@ViaConstructor` holds its order to the constructor** ([#906](https://github.com/higher-kinded-j/higher-kinded-j/issues/906)). An order that passes a value where the constructor's parameter names say another belongs, or that no constructor takes, is now refused at the spec method. Leave `parameterOrder` out and it is read from those names. See [`@ViaConstructor`: constructor-only value types](../optics/copy_strategies.md#viaconstructor-constructor-only-value-types).
- **A `@ViaConstructor` order that leaves a value out says so** ([#1067](https://github.com/higher-kinded-j/higher-kinded-j/issues/1067)). A written order that rebuilds through a shorter constructor now warns, naming the values longer constructors take that the order leaves out. `@SuppressWarnings("shorter-constructor")` keeps quiet a constructor that works the value out on purpose. A variable-arity constructor is held to its parameter names too. See [the warning's entry](../optics/compiler_errors.md#viaconstructor-shorter-constructor).
- **A `@ViaCopyAndSet` lens keeps what its `withX` setter returns** ([#1108](https://github.com/higher-kinded-j/higher-kinded-j/issues/1108)). A `withTitle` setter had its new value dropped. The lens now hands back what it returns where every method of that name the new value can be passed to returns the source type. One it cannot keep warns, unless the lens method is annotated `@SuppressWarnings("dropped-result")`. See [`@ViaCopyAndSet`](../optics/copy_strategies.md#viacopyandset-legacy-types-with-a-copy-constructor-and-setters).
- **`@ImportOptics` takes no word for a wither** ([#1128](https://github.com/higher-kinded-j/higher-kinded-j/issues/1128)). A name that runs on in lower case after `with` is a word, so a `withdraw(long)` beside `getDraw()`, which gave a `draw` lens that added to `draw` rather than setting it, now gives none. A `with2D(int)` beside `get2D()` no longer stops the processor. See [Wither Classes to Lenses](../optics/importing_optics.md#wither-classes-to-lenses).
- **A spec lens that would read or rebuild unchecked through a raw type is refused at the spec method** ([#905](https://github.com/higher-kinded-j/higher-kinded-j/issues/905)). A raw accessor read as `List<String>`, or a setter called through a raw builder, left an unchecked operation in generated code, which failed a build under `-Xlint:unchecked -Werror`. The error names the member at fault. See [Compiler Errors](../optics/compiler_errors.md#spec-unchecked-conversion).
- **Optics over a nullable field pass a nullness checker** ([#767](https://github.com/higher-kinded-j/higher-kinded-j/issues/767), [#1017](https://github.com/higher-kinded-j/higher-kinded-j/issues/1017)): every optic and Focus path type, and `Kind`, takes a nullable type, so the lens generated for a `@Nullable` component checks under JSpecify. A bridge into an effect type can say what a null focus becomes, as `toEitherPath(source, error)` does. See [A focus that may be null](../optics/focus_effects.md#a-focus-that-may-be-null).
- **`nullable()` keeps the focus type** ([#1017](https://github.com/higher-kinded-j/higher-kinded-j/issues/1017)): `FocusPath.nullable()` and `AffinePath.nullable()` return the focus type without its null, so a chained `focus(path.nullable(), error)` or a `var` infers it where it inferred `Object`. A call written `path.<String>nullable()` still compiles. See [`.nullable()`: Handle Null Values](../optics/focus_navigation.md#nullable-handle-null-values).
- **A Focus path through a custom container whose generator names no optic stops at the container** ([#1059](https://github.com/higher-kinded-j/higher-kinded-j/issues/1059)), as if no generator supported it. It used to widen through the `Optional`-only `.some()` or the `List`-only `.each()`, and threw `ClassCastException` on first use for other containers. The generator still serves `@GenerateTraversals` and `@ImportOptics`. See [Registering your own container type](../optics/focus_containers.md#the-fine-print-registering-your-own-container-type).
- **A `Maybe` component's Focus path reads and writes its `Just` value** ([#757](https://github.com/higher-kinded-j/higher-kinded-j/issues/757)): `@GenerateFocus` now widens a `Maybe` field through `.some(Affines.just())`. It used the `Optional`-only `.some()`, so the first read or write of the path threw `ClassCastException`. A `Maybe` nested in another container, such as `List<Maybe<A>>`, threw the same way. See [Supported Container Types](../optics/focus_containers.md#supported-container-types).
- **`Setter.forList` and `Setter.forMapValues` give the same result on every run** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): each time the effect from `modifyF` runs, it builds its own list or map. So an `IO` gives an equal value on every run, and the `List` applicative gives every combination of choices. `Traversals.traverseMapValues` does the same for an empty map. See [Sequencing Effects in Collections](../optics/setters.md#sequencing-effects-in-collections).
- **A read through a traversal no longer rebuilds what it reads** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)). `Traversals.getAll`, a `TraversalPath`'s reads, `IndexedTraversals.toIndexedList`, `getAll` and `length`, `asIndexedFold()` and `IxedInstances.get` read each focus as `asFold()` does. So reading a list or map through an optic no longer builds a new one. See [What reads cost](../optics/production_readiness.md#read-cost).
- **A fold's query stops at its answer** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)). `preview`, `find`, `exists`, `all` and `isEmpty` on `Fold` and `TraversalPath`, and `IndexedFold`'s queries, visit no focus after the one that settles them. So `exists` over a long list returns at its first match. A path from `traced` still reads every focus, so its observer sees them all. See [What reads cost](../optics/production_readiness.md#read-cost).
- **A prism or affine that matches builds nothing it throws away** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)). `Prism.modifyF`, `Affine.modifyF`, `Traversal.andThen(Prism)`, `Prism.andThen(Traversal)` and `Affine.andThen(Traversal)` wrap the source with `of` only on a miss, and `OptionalTraverse.traverse` only for an empty `Optional`. See [Prisms and affines on a miss](../optics/production_readiness.md#prisms-and-affines).
- **A navigator reaches into a generic record** ([#739](https://github.com/higher-kinded-j/higher-kinded-j/issues/739)): a field such as `Revision<EmailAddress> email` gets a navigator instantiated with its type arguments, so `ContactHistoryFocus.email().current()` chains as it would into any other record. A field given a wildcard or no type arguments gets no navigator, and its note no longer suggests a chain through `RevisionFocus`. See [A target with type parameters](../optics/focus_navigation.md#a-target-with-type-parameters).
- **A missing navigator's note names the path the field's method returns** ([#1061](https://github.com/higher-kinded-j/higher-kinded-j/issues/1061)). That is an `AffinePath` for an `Either` or a `@Nullable` field, and a `TraversalPath` for a `Map` or array under `widenCollections`. For a generic record given a wildcard, the note adds that a lens you write from that type composes. See [A target with type parameters](../optics/focus_navigation.md#a-target-with-type-parameters).
- **A prism onto an inner class of a generic class compiles under `-Werror`** ([#886](https://github.com/higher-kinded-j/higher-kinded-j/issues/886)): a `Dot` declared inside `class Outlines<X>` gets `Prism<Outlines.Outline, Outlines<?>.Dot>`, from `@GeneratePrisms`, `@ImportOptics` and an `@InstanceOf` spec method. A generic inner class gets a prism too, where `@InstanceOf` refused one. See [Generating the Prisms](../optics/prisms.md#step-1-generating-the-prisms) and [Parameterised Targets](../optics/optics_spec_interfaces.md#parameterised-targets).
- **`@InstanceOf` reports a source argument outside the target's bound at the spec method** ([#1082](https://github.com/higher-kinded-j/higher-kinded-j/issues/1082)). A `Gauge<Y extends Number>` reached from a `Node<U>` whose `U` could be anything used to fail in the generated file, where javac refused `Gauge<U>`. The message now lands on the spec method, and where one bound would do, gives the declaration to write. See [Parameterised Targets](../optics/optics_spec_interfaces.md#parameterised-targets).
- **`@InstanceOf` refuses a test that could never match, where it crashed on one** ([#1091](https://github.com/higher-kinded-j/higher-kinded-j/issues/1091)). A `Grid<Y> extends Node<Y[]>` reached from a `Node<int[]>` crashed the processor. It is now refused at the spec method, as is a class that writes a different type from the source's where no choice of its parameters makes the two agree. See [the message's entry](../optics/compiler_errors.md#instanceof-never-matches).
- **An `@InstanceOf` message no longer offers a focus the next check refuses** ([#1091](https://github.com/higher-kinded-j/higher-kinded-j/issues/1091)). Where what the test earns is no source type, as a `Box<?>` is no `Node<U>`, it says no focus would do, and offers another class or a spec of its own over `Node<List<X>>`. See [the message's entry](../optics/compiler_errors.md#instanceof--declares-its-focus-as-circlet-which-the-test-cannot-narrow-to).
- **A method named after a Java keyword takes a trailing underscore** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)). An enum constant such as `NEW` or `TRUE`, a sealed subtype named `Default`, an `@EffectAlgebra` permit named `Throw`, or an imported `withDefault` crashed the processor. Their methods are now `new_()`, `true_()`, `default_()` and `throw_()`, and so are `@GenerateErrorEnvelope` factories. See [Prisms](../optics/prisms.md).
- **`.each()` on a `List` path takes time in proportion to the list** ([#1063](https://github.com/higher-kinded-j/higher-kinded-j/issues/1063)). A Focus path's `.each()`, which every generated `List` path uses, now rebuilds the list once instead of copying it at every element. On 100,000 elements that took several seconds, and now takes about a millisecond. `EachInstances.arrayEach()` rebuilds an array the same way. See [Traversal allocation](../optics/production_readiness.md#traversal-allocation).
- **`modifyAllEither`, `modifyAllValidated` and `modifyAllMaybe` keep a null element their traversal passes over** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): over `filtered` or a prism that leaves a null element alone, `modifyAllValidated` threw and `modifyAllMaybe` gave `Nothing`. Each now keeps the null, and still rebuilds nothing once a step fails. So do `OpticOps`' validating modifiers. See [`modifyAllEither`: First Error Only](../optics/optics_extensions.md#modifyalleither-first-error-only).
- **`@GenerateFocus` widens an array, as the Focus pages say** ([#1062](https://github.com/higher-kinded-j/higher-kinded-j/issues/1062)). Under `widenCollections = true`, a `String[]` or other array of a reference type is a `TraversalPath` over its elements, and an array of `@GenerateFocus` records gets a navigator over them. A primitive array stays a plain path. See [Supported Container Types](../optics/focus_containers.md#supported-container-types).
- **A `@Nullable` container's Focus path is empty when the container is null** ([#1062](https://github.com/higher-kinded-j/higher-kinded-j/issues/1062)). A `@Nullable` `List`, `Set`, `Optional`, `Either` or other container that its path steps into now widens through `.nullable()` first, where its path threw `NullPointerException`. So does a nullable container inside another, such as `List<@Nullable List<String>>`. The path type is the same. See [Where a `@Nullable` counts](../optics/focus_navigation.md#where-a-nullable-counts).
- **A navigator passes over a null element it would read** ([#1062](https://github.com/higher-kinded-j/higher-kinded-j/issues/1062)). A navigator into `Map<String, @Nullable Address>`, or into an array of nullable records, failed a nullness checker and threw `NullPointerException` on a null element. It now reads the other elements and leaves the null in place.

## Effect Paths {#effect-paths}

- **A deferred trampoline step names a supplier that returns null** ([#1153](https://github.com/higher-kinded-j/higher-kinded-j/issues/1153), [#1161](https://github.com/higher-kinded-j/higher-kinded-j/issues/1161)): `Trampoline.defer`, `TrampolinePath.defer` and `Path.trampolineDefer` report `supplier must not return null` when that step runs. The supplier stays lazy.
- **`StateT` is built from its state function alone** ([#445](https://github.com/higher-kinded-j/higher-kinded-j/issues/445)): its constructor, `create` and `StateTKindHelper.stateT` take no `Monad`, and `mapT` takes only the transformation, as on every other transformer. The record holds only that function, so `equals`, `hashCode` and `toString` leave the `Monad` out. See [Running StateT Computations](../transformers/statet_transformer.md#running-statet-computations).
- **`Try` and `TryPath` fold failure first, as `Either` does** ([#452](https://github.com/higher-kinded-j/higher-kinded-j/issues/452)): the success-first `fold`, deprecated since 0.4.6, is removed, leaving `foldFailureFirst`. A call to `fold` fails to compile rather than running its two functions the wrong way round. See [Handling Failures](../monads/try_monad.md#handling-failures-foldfailurefirst-recover-recoverwith).
- **`@PathSource` points an effect algebra to `FreePath`** ([#1008](https://github.com/higher-kinded-j/higher-kinded-j/issues/1008)): a Path over a witness that `@EffectAlgebra` generates now draws a note at the witness. The algebra has a `Functor` and no `Monad` to pass to the Path's `of` and `pure`, so the note shows how to wrap its programs in a `FreePath`. See [A witness another processor writes](../effect/path_source.md#a-witness-another-processor-writes).
- **`TrampolineUtils.traverseListStackSafe` is stack-safe under every applicative** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): it combines the effects as a balanced tree, so a million-element traversal under `IO` no longer overflows the stack. It builds the result in linear time instead of copying the list at every element, and a `Validated` collecting its errors in a list is no longer quadratic in the failures. See [Core Components](../monads/trampoline_monad.md#core-components).
- **A `VStream` releases its resources when it stops early or fails** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): closing reaches every finaliser upstream that the stream has started reading, through any operator, innermost first. `takeWhile`, `zipWith`, `headOption`, `find`, `exists`, `forAll` and a failing terminal operation close what they leave unread. So `bracket(...).map(f).headOption()` releases at once. `VStream.closeAfterFailure` closes a failed manual pull. See [onFinalize: Lightweight Cleanup](../monads/vstream_resources.md#onfinalize-lightweight-cleanup).
- **One `Resource` can serve overlapping uses** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019)): each `use` releases exactly what it acquired, however the `Resource` was composed. So a `Resource` built once with `map` or `flatMap` and used nested, or once per concurrent request, no longer releases one resource twice and leaks the other. See [Using One Resource Many Times](../monads/vtask_resource.md#using-one-resource-many-times).
- **`bracket`, `guarantee` and `withResource` report a failing cleanup as try-with-resources does** ([#1053](https://github.com/higher-kinded-j/higher-kinded-j/issues/1053)): when a use fails and its cleanup throws too, `IOPath` and `VTaskPath` report the use's exception with the cleanup's suppressed onto it. `withResource`, `withResourceIO` and `Resource.fromAutoCloseable` report an exception from `close()`, so a writer whose final flush fails no longer reports success. See [The bracket Pattern](../effect/advanced_topics.md#the-bracket-pattern).
- **A release that blocks finishes after a cancellation** ([#1057](https://github.com/higher-kinded-j/higher-kinded-j/issues/1057), [#1073](https://github.com/higher-kinded-j/higher-kinded-j/issues/1073)): it runs with the interrupt status cleared, then restored. That covers a `bracketOutcome` release, a release after a use that caught a cancellation and returned, and each `Saga` compensation. A blocking release, such as a refund, used to fail at once. See [The bracket Pattern](../effect/advanced_topics.md#the-bracket-pattern) and [Saga](../resilience/saga.md#handling-compensation-failures).
- **`VStreamReactive` passes cancellation across the bridge** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): a `toPublisher` subscription closes the rest of its stream when it cancels or the stream fails, once it has requested elements. Closing a `fromPublisher` stream cancels its subscription, so `take(n)` stops the publisher. See [Reactive Interop: Flow.Publisher Bridge](../monads/vstream_advanced.md#reactive-interop-flowpublisher-bridge).
- **A `Scope` can run again, be retried, or run on several threads** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): each run of the `VTask` from `join()` opens its own `StructuredTaskScope` with a new `Joiner`. A second run used to see the first run's results, and a retry kept failing with the first attempt's error. `VResultPath.allSucceed`, `allSucceedAccumulating` and `firstSuccess` are fixed too. See [Running a Scope Again](../monads/vtask_scope.md#running-a-scope-again).
- **Resilience patterns keep a task's exception and its cancellation** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): `Retry.retryTask`, `Bulkhead.protect` and their Path forms, and `CircuitBreaker.protectWithFallback`, no longer wrap a checked exception, so `retryOn(IOException.class)` retries a task's `IOException`. A cancelled task is not run again or counted by a circuit breaker, and a timeout passes the cancellation on. See [Handling Exhausted Retries](../resilience/retry.md#handling-exhausted-retries).
- **A `Right` or a `Success` always holds a value** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): `Either.right`, `Try.success`, their Path, `EitherT` and `ErrorContext` factories, and `of` on their monads, refuse null, as `Validated` and `EitherOrBoth` already did. A step that succeeds with nothing to return gives `Unit.INSTANCE`, as `VTask.exec`, `Path.vtaskExec` and `Path.ioRunnable` already do. See [Creating Instances](../monads/either_monad.md#creating-instances).
- **A `Left` always holds an error** ([#1077](https://github.com/higher-kinded-j/higher-kinded-j/issues/1077)): `Either.left`, `EitherT.left`, `raiseError` on `EitherMonad` and `EitherTMonad`, and `Maybe.toEither` refuse null, as every Effect Path has done since 0.4.11. An error with no detail to carry is `Unit.INSTANCE`. See [Creating Instances](../monads/either_monad.md#creating-instances).
- **`bracketOutcome`'s release sees its error as a `Maybe`** ([#1077](https://github.com/higher-kinded-j/higher-kinded-j/issues/1077)): release takes an `Either<Maybe<E>, B>`. A typed failure arrives as `Left(Just(e))`, and a failed `onDefect` as `Left(Nothing)`, where it was `Left(null)`. A release lambda that never reads the error needs no change. See [Outcome-aware structured concurrency](../effect/path_vresult.md#outcome-aware-structured-concurrency).
- **A lazy computation always gives a value** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `IO`, `VTask`, `VStream`, `State`, `Lazy` and the other lazy types, and every Path over them, refuse a null value, as `Either` and `Try` do. A value passed in throws at the call, and a function that returns null fails the computation when it runs. See [A Task Always Gives a Value](../monads/vtask_monad.md#a-task-always-gives-a-value).
- **Every `raiseError` refuses a null error** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `MonadError.raiseError` takes an error that is never null, so a nullness checker flags `raiseError(null)` on any instance. `Maybe`, `Optional`, `MaybeT` and `OptionalT`, whose failure carries no detail, take `Unit.INSTANCE`. See [The Solution: `raiseError` and `handleErrorWith`](../functional/monad_error.md#the-solution-raiseerror-and-handleerrorwith).
- **The Path SPI answers with an `Optional` where it has nothing to give** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `PathProvider.monadError()` and `PathRegistry.unregister` return an `Optional`, as `PathRegistry.getProvider` and `GenericPath.monadError()` do, where they returned null. See [PathProvider SPI Registration](../monads/vstream_advanced.md#pathprovider-spi-registration).

## Upgrading from 0.4.11 {#upgrading}

### Before you upgrade {#before-you-upgrade}

- **Run `MigrateDeprecationsTo0_5_0` before you move to 0.5.0** ([#445](https://github.com/higher-kinded-j/higher-kinded-j/issues/445), [#452](https://github.com/higher-kinded-j/higher-kinded-j/issues/452)): take `hkj-openrewrite` 0.5.0 for the run, and keep the project on 0.4.11 until it finishes. Its `StateT` and `Try.fold` recipes match the 0.4.x signatures, so they rewrite nothing once the build resolves 0.5.0. See [0.5.0 deprecation migration](../tooling/openrewrite.md#050-deprecation-migration).
- **Replace `Void` with `Unit` where a success has nothing to return** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065), [#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `Either<E, Void>` and `Try<Void>` can no longer hold their null. A `VTask<Void>`, `IOPath<Void>` or other lazy computation fails when its step returns null. `VTask.exec`, `Path.vtaskExec` and `Path.ioRunnable` give `Unit`. The `MigrateDeprecationsTo0_5_0` run marks each site.

- **Recompile what was compiled against a generated Focus class** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033), [#1214](https://github.com/higher-kinded-j/higher-kinded-j/issues/1214)): a field or a hop that gains a navigator returns a navigator class. A module compiled against the earlier class fails with `NoSuchMethodError` until it is rebuilt.

### What a running program can notice {#runtime-changes}

- **Uppercase warning settings take effect on Turkish systems** ([#1168](https://github.com/higher-kinded-j/higher-kinded-j/issues/1168)): remove any workaround that lowercased `WARNING` before passing it to the checker. Generated for-comprehension lambda names now use `i` rather than dotless `ı`; tuple constant names are unchanged. Numeric log counts use the root locale's digits. No source changes are required.

#### Mapping {#runtime-mapping}

- **A bean property is read through its accessor, never a word declared before it** ([#1128](https://github.com/higher-kinded-j/higher-kinded-j/issues/1128)): a `getaway()` or `island()` declared before `getAway()` or `isLand()` read `away` or `land`, and the accessor now does.
- **A merge fill can parse through a generic spec in this compilation** ([#1123](https://github.com/higher-kinded-j/higher-kinded-j/issues/1123)): a dependency's spec for exactly the pair used to fill it. It now resolves as a mapping's nest does, your own specs first. A leaf named after the component, delegating to the dependency's Impl, keeps the old fill.

#### Optics {#runtime-optics}

- **A `@GenerateFocus` record field, or a container of one, returns a navigator** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033), [#1103](https://github.com/higher-kinded-j/higher-kinded-j/issues/1103), [#1214](https://github.com/higher-kinded-j/higher-kinded-j/issues/1214)): a `getClass()` check sees the navigator class, as it does the form a hop from a wider navigator returns. A navigator equals only a navigator of the same class over an equal path, never the plain path it wraps.
- **A navigator is a path** ([#1033](https://github.com/higher-kinded-j/higher-kinded-j/issues/1033)): one from a record that wrote `generateNavigators = true` passes `instanceof FocusPath`, and an overload taking a `FocusPath` is chosen over one taking `Object`.
- **A map an optic writes iterates in the source's order** ([#1022](https://github.com/higher-kinded-j/higher-kinded-j/pull/1022)): it came back in hash order, so printed output or a test of a map's iteration order can change. `FocusPaths.mapValues` over an empty map returns a new map.
- **A `TreeMap` keeps its order but not its type** ([#1022](https://github.com/higher-kinded-j/higher-kinded-j/pull/1022)): `forMapValuesCollecting(TreeMap::new)` keeps both when the keys sort in their natural order. A `TreeMap` with its own comparator needs a collector that builds the new `TreeMap` with that comparator.
- **The function a predicate does not pick is no longer called** ([#1026](https://github.com/higher-kinded-j/higher-kinded-j/pull/1026)): by `modifyWhen` and `branch` on a `Traversal`, and by `modifyWhen` and `modifyBranch` on a `Lens`. `Lens.setIf` no longer calls `set` on a failed predicate. So a logging, counting or throwing function sees only the values its predicate picks. `Traversals.speculativeTraverseList` is unchanged: it applies both functions to every element.
- **A read through an `Optional` or a `Maybe` reads a null focus as absent** ([#767](https://github.com/higher-kinded-j/higher-kinded-j/issues/767)): `Fold.preview`, `TraversalPath.preview` and `toMaybePath`, and `FocusPath.toMaybePath` used to throw `NullPointerException`. So did `FocusPath.asAffine`, `headOption`, `IxedInstances.get` and the list optics `listAt`, `listHead` and `listLast`, whose setters, and the list prisms' `build`, now write a null.
- **`find` passes over a null focus to the next match** ([#767](https://github.com/higher-kinded-j/higher-kinded-j/issues/767)): on `Fold`, `TraversalPath`, `OpticOps` and `FoldExtensions`, where a null match threw.
- **The element optics carry a null element through** ([#767](https://github.com/higher-kinded-j/higher-kinded-j/issues/767)): `Setter.forList`, and `FocusPaths.listElements`, `arrayElements`, `listCons`, `listSnoc`, `listTail`, `listInit` and `mapValues`, used to throw.
- **`Plans.preflight` walks a batched traversal to the end** ([#767](https://github.com/higher-kinded-j/higher-kinded-j/issues/767)): `truncated` is now `false` for one, since the walk's null stub values no longer halt it.
- **`IxedInstances.contains` counts an index holding a null as present** ([#767](https://github.com/higher-kinded-j/higher-kinded-j/issues/767)).
- **A traversal's Effect Path bridges leave a null focus out** ([#1017](https://github.com/higher-kinded-j/higher-kinded-j/issues/1017)): `toStreamPath`, `toVStreamPath` and `VStreamPath.fromEach` used to stream it, and `toListPath` and `toNonDetPath` threw `NullPointerException`. `TraversalPath.fold` counts it as the monoid's empty value, where `Monoids.string()` appended `"null"`. `getAll` still keeps every focus.
- **Sequenced lists are unmodifiable at every size** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): `IndexedTraversals.sequenceList`, `ForTraversal.toList` and `ForIndexed.toIndexedList` now return one, as `Traversals.traverseList` does. So do `IndexedTraversals.forList` on a non-empty list and `Traversals.traverseArray` on an empty array. Changing the result throws `UnsupportedOperationException`, so copy it into a new `ArrayList` first.
- **A `@ViaConstructor` lens with no `parameterOrder` sets through its constructor** ([#906](https://github.com/higher-kinded-j/higher-kinded-j/issues/906)): the order is read from the constructor's parameter names, where `set` used to throw `UnsupportedOperationException`.
- **A `@ViaCopyAndSet` lens over a `withX` setter hands back what it returns** ([#1108](https://github.com/higher-kinded-j/higher-kinded-j/issues/1108), [#1128](https://github.com/higher-kinded-j/higher-kinded-j/issues/1128)): not the copy, where every method of that name the new value can be passed to returns the source type. A fluent `withX` behaves as before, and so does every `set` method. A `witheMail`, as JavaBeans spells one for `eMail`, is a `withX` setter too.
- **A spec lens whose focus is wider than its getter's wrapper passes the value as it is** ([#906](https://github.com/higher-kinded-j/higher-kinded-j/issues/906)): with `Number` over an `int` getter, it used to be cast to `int` for `withX(int)`. Where the wither, setter or constructor is also overloaded for a wider type, such as `withX(Object)`, that overload is now the one called.
- **`ForTraversal.toList` and `ForIndexed.toIndexedList` honour the filters** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): they collect only the elements that pass `filter` and `filterIndex`, as `modify` and `set` already did. They used to return every focused element. See [Collecting Results](../functional/for_optics.md#collecting-results).
- **A query's predicate is not called after its answer** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)): `find`, `exists` and `all`, on `Fold`, `IndexedFold` and `TraversalPath`, stop at the focus that settles them, so a logging or counting predicate sees fewer calls. A `Fold` of your own whose `foldMap` catches every exception still gives the same answer, but walks on to its end.
- **A read no longer runs a traversal's rebuild** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)): a `Traversal` of your own whose rebuild logs or counts no longer runs it for `Traversals.getAll`, a `TraversalPath`'s reads, `IndexedTraversals.toIndexedList`, `getAll` and `length`, or `asIndexedFold()`.
- **`OptionalTraverse.traverse` rejects a function that returns null** ([#1056](https://github.com/higher-kinded-j/higher-kinded-j/pull/1056)). For a present value, a `null` from the function used to give an empty `Optional`. It now throws `NullPointerException`, as the other `Traverse` instances do.
- **The list optics that returned an `ArrayList` now return an unmodifiable list** ([#1063](https://github.com/higher-kinded-j/higher-kinded-j/issues/1063)): `.each()`, `.at(i)`, `.head()` and `.last()` on a Focus path, `ListTraversals`, `AtInstances.listAt` and `listAtWithPadding`, and `IxedInstances.listIx`. Changing a returned list throws `UnsupportedOperationException`, so copy it first. With nothing at the index, `.at(i)` and `listIx` return your own list. See [What each collection optic builds](../optics/production_readiness.md#collection-optics).
- **A Focus path over a field declared as `ArrayList` fails when `.each()`, `.at(i)`, `.head()` or `.last()` writes** ([#1063](https://github.com/higher-kinded-j/higher-kinded-j/issues/1063)): storing the rebuilt list, an unmodifiable `List`, back throws `ClassCastException`. `.each()` already failed on a one-element list. Declare the field as `List`, or use `each(EachInstances.fromIterableCollecting(ArrayList::new))`.
- **`.each()` over an empty list, and `arrayEach().each()` over an empty array, return a new empty one** ([#1063](https://github.com/higher-kinded-j/higher-kinded-j/issues/1063)): not the source itself.
- **A raw `modifyF` under `Either` or `Try` cannot pass over a null element** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): `filtered` keeps an element it passes over by lifting it with `of`, as do a prism and an affine that miss. Under those applicatives `of` now refuses null. `TraversalExtensions.modifyAllEither` and its siblings keep the element.
- **A null `@Nullable` container has no focus** ([#1062](https://github.com/higher-kinded-j/higher-kinded-j/issues/1062)): a generated Focus path that steps into one reads nothing, and a modification leaves it null, where both threw `NullPointerException`.
- **`OpticPrograms.get` fails on a null focus, naming `preview`** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): a Free program always gives a value, so the direct and logging interpreters throw `NullPointerException`, and `ValidationOpticInterpreter` records an error. `StateOps.view` on a null focus fails the same way.
- **A `@ViaBuilder` lens over a Lombok `@Singular` collection, or through a protobuf-java message's `addAllTags` or `putAllPoints`, replaces the collection** ([#1110](https://github.com/higher-kinded-j/higher-kinded-j/issues/1110)): `set` used to add the new elements to the ones `toBuilder()` copied. Code that set a one-element list to add an element now keeps only that element; append with `modify` instead.

#### Effect Paths {#runtime-effect-paths}

- **A null result from a deferred trampoline step names its supplier** ([#1153](https://github.com/higher-kinded-j/higher-kinded-j/issues/1153), [#1161](https://github.com/higher-kinded-j/higher-kinded-j/issues/1161)). It is still a `NullPointerException`, raised when the step runs: from `run()` for `Trampoline.defer`, and from the deferred step for `TrampolinePath.defer` and `Path.trampolineDefer`. No call site needs to change.
- **`StateT` equality leaves out the `Monad`** ([#445](https://github.com/higher-kinded-j/higher-kinded-j/issues/445)): two `StateT` values wrapping the same function instance are equal, with equal hash codes, whichever `Monad` built them. `toString` prints only `runStateTFn`, so a test comparing the old text fails.
- **A list from `PathOps` or `Par` cannot be changed** ([#1017](https://github.com/higher-kinded-j/higher-kinded-j/issues/1017)): the `sequence` and `traverse` methods, `Par.all` and `Par.traverse` handed back their working `ArrayList`. So changing the list inside an `EitherPath` changed what every later `run()` saw. Changing one now throws `UnsupportedOperationException`, so copy it into a new `ArrayList` first.
- **`TrampolineUtils.traverseListStackSafe` and `sequenceStackSafe` return an unmodifiable list** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): as `Traversals.traverseList` does. Changing it throws `UnsupportedOperationException`, so copy it into a new `ArrayList` first.
- **`onFinalize` runs its finaliser for each consumption of a `VStream`** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): a second consumption, or one after `close()`, used to skip it. It now also runs when the source fails as it is pulled. `close()` runs it for the latest consumption only, unless that consumption has run it already. See [onFinalize: Lightweight Cleanup](../monads/vstream_resources.md#onfinalize-lightweight-cleanup).
- **`VStreamThrottle.throttle` gives each consumption its own window** ([#1018](https://github.com/higher-kinded-j/higher-kinded-j/issues/1018)): each consumption's first emission opens its first window. A later or concurrent consumption used to share the first one's window.
- **`VStream.defer` calls its supplier when the pulled `VTask` runs** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): not when `pull()` is called, and again on each run. `generate`, `iterate` and `unfold` call their functions then too. `distinct`, `chunk` and `chunkWhile` now give the same step each time a pulled `VTask` runs, and a `distinct` tail pulled again replays its elements.
- **`VStreamPar.parEvalMap`, `parEvalMapUnordered` and the `VStream` applicative's `ap` read their input when the pulled `VTask` runs** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): not when `pull()` is called, and afresh on each run.
- **Closing a pulled `bracket` stream releases its latest run** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): closing the head of a `bracket` after a pull releases the resource that pull acquired, where it used to release nothing.
- **A finaliser that used to be skipped now runs** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): when a `VStream` stops early, a terminal operation fails, or a function given to an operator such as `map`, `filter` or `mapTask` throws. A finaliser that throws then fails the operation that stopped, such as `take` or `headOption`. Closing runs the innermost finaliser first, as completing does.
- **`VStreamPar.merge` starts a producer for each run of its pulled `VTask`** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024), [#1073](https://github.com/higher-kinded-j/higher-kinded-j/issues/1073)): not when `pull()` is called. Closing it stops that run's producer and waits for each unfinished source to close, even with an interrupt pending. `close()` used to stop the producer when called; now it works when its `VTask` runs. See [merge: Concurrent Multi-Source Consumption](../monads/vstream_parallel.md#merge-concurrent-multi-source-consumption).
- **Cancelling a `toPublisher` subscription runs the stream's finalisers** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): once the subscriber has requested elements. It used to leave the stream open.
- **`Resource.onFailure` runs its action when the use fails** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019)): it used to do nothing. The action runs before the release, both when the use fails and when a step composed after it fails while the resource is held, such as `map`'s function throwing. See [onFailure Callback](../monads/vtask_resource.md#onfailure-callback).
- **`Resource.map` releases the resource when its function throws** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019)): it used to leave the resource acquired.
- **A `Resource` rejects a null value** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019)): an `acquire` given to `make` or `fromAutoCloseable` that returns null, a null passed to `pure`, and a function given to `map` that returns null now fail with `NullPointerException`. A null used to be passed on to the use function. Hold an absent value as a `Maybe` instead. See [Factory Methods](../monads/vtask_resource.md#factory-methods).
- **A failing use keeps its own exception when cleanup fails too** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019), [#1053](https://github.com/higher-kinded-j/higher-kinded-j/issues/1053)): in a `Resource`, and in `IOPath.bracket`, `bracketIO`, `guarantee`, `guaranteeIO` and `VTaskPath.guarantee`, the cleanup's exception is kept among the use's suppressed exceptions. When a release and a finaliser both throw, the release's exception is reported. The last exception thrown used to replace the others. See [Exception Safety](../monads/vtask_resource.md#exception-safety).
- **`and(second, third)` releases its first resource when two releases throw one exception** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019)): the same exception instance from both used to fail with `IllegalArgumentException` and leave the first resource acquired.
- **Cleanup runs with the interrupt status cleared** ([#1019](https://github.com/higher-kinded-j/higher-kinded-j/issues/1019), [#1053](https://github.com/higher-kinded-j/higher-kinded-j/issues/1053), [#1057](https://github.com/higher-kinded-j/higher-kinded-j/issues/1057), [#1073](https://github.com/higher-kinded-j/higher-kinded-j/issues/1073)): after any use, in `Resource`, `IOPath`, `VTaskPath`, `VStream` finalisers, `bracketOutcome` and each `Saga` compensation. So a blocking close is not cut short, and a `Scope` that timed out during the use waits for it. The status is restored afterwards. `withResource` also sets it when `close()` throws an `InterruptedException`.
- **A cancelled `bracketOutcome` use leaves the thread interrupted** ([#1057](https://github.com/higher-kinded-j/higher-kinded-j/issues/1057)): when the use throws an `InterruptedException`, the interrupt status is set again once the release has run. The thread's next blocking call then throws `InterruptedException` at once. The interrupt used to be lost. To tell a cancellation from other failures, map `InterruptedException` to its own error in `onDefect`.
- **A task's checked exception passes through `Retry`, `Bulkhead` and `protectWithFallback` unwrapped** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): `Bulkhead.protect`, `Retry.retryTask` and its fallback and recovery forms, and `withBulkhead` and `withRetry` on `VTaskPath` and `VResultPath`, used to wrap it in `VTaskExecutionException`. `CircuitBreaker.protectWithFallback` wrapped it, and an `Error`, in `RuntimeException`. A `retryOn` predicate, a fallback and `RetryExhaustedException.getCause()` now see the exception itself.
- **An interrupt stops a retry** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): an attempt that throws `InterruptedException` is not tried again, whatever the predicate, and the exception passes through as thrown, past any fallback. A thread left interrupted between attempts stops the retry with its status set and `RetryExhaustedException`, which a fallback still handles. A recovery task does not start after either.
- **A timeout passes a cancellation on** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): when a thread waiting on `VTask.timeout` is interrupted, so is the task, and `InterruptedException` follows once it stops or the time runs out. It used to leave the task running and report its result or a `TimeoutException`. `withTimeout` on `VTaskPath`, `IOPath`, `VResultPath` and `EitherPath` builds on it.
- **A cancelled call trips no circuit breaker and skips a `ResilienceBuilder` fallback** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): a call that throws `InterruptedException` counts as neither a success nor a failure, whatever `recordFailure` says. The fallback lets it pass.
- **`VTask.run()`, `runSafe()` and `Try.attempt` keep a cancellation's interrupt status** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): each sets it again for an `InterruptedException` it wraps or returns as the failure, and the Path forms built on them follow. So a retry around `IOPath.withTimeout` sees the cancellation and stops. The thread's next blocking call then throws at once, where the status used to be cleared.
- **An extremely long duration no longer throws** ([#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): a duration too long to count in nanoseconds, such as `ChronoUnit.FOREVER.getDuration()`, counts as about 292 years. That holds for timeouts, a bulkhead's wait, retry delays, a `VStream` throttle window and a circuit breaker's `retryAfter`, where some threw `ArithmeticException`. Sub-millisecond parts are kept, where `RetryPolicy` and several waits dropped them.
- **An exception from `close()` fails `withResource`, `withResourceIO` and `fromAutoCloseable`** ([#1053](https://github.com/higher-kinded-j/higher-kinded-j/issues/1053)): it used to be dropped. After a successful use, `IOPath` throws it unchecked, a `SQLException` as the cause of a `RuntimeException`, and the task from `Resource.use` fails. After a failed use, it is suppressed onto the use's. To ignore it, pass `bracket` or `Resource.make` a release that catches it.
- **`withResource` and `withResourceIO` reject a null resource** ([#1053](https://github.com/higher-kinded-j/higher-kinded-j/issues/1053)): a resource supplier that returns null now fails with `NullPointerException` before the use runs. The use used to receive the null. Check for an absent resource before building the path.
- **A `bracket` whose `use` function throws releases the resource** ([#1024](https://github.com/higher-kinded-j/higher-kinded-j/issues/1024)): before the failure reaches the caller. It used to leave the resource acquired.
- **`Scope.firstComplete` and `ScopeJoiner.firstComplete()` cancel the other subtasks once one completes** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): they used to wait for every subtask. Those still running are interrupted and those not yet started never start, so work a slower subtask does afterwards, such as writing a cache, no longer happens. Move work that must finish out of the race.
- **`ScopeJoiner.joiner()` returns a new `Joiner` on each call** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): code that opened a scope with one call and read `result()` from another now reads a `Joiner` no scope has used. That gives an empty result or an exception, so use the value the scope's `join()` returns.
- **A `Scope`'s timeout cancels its subtasks** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): when it expires, those still running are interrupted, and the run fails with a `TimeoutException` once they have stopped. They used to keep running unobserved, so a subtask that ignores interrupts now delays the failure. Its subtasks now see the caller's `ScopedValue` bindings, which they used to find unbound.
- **An interrupt while a timed `Scope` waits fails the run** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): with an `InterruptedException`, as it does for an untimed `Scope`. A timed one used to ignore it and keep waiting.
- **`Par` and `PathOps` copy the list they are given when called** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): `Par.race`, `all` and `traverse`, and `PathOps.sequenceVTask`, `traverseVTask`, `firstVTaskSuccess`, `parSequenceIO` and `raceIO`. Changing the list afterwards no longer changes what a run does. A null task or path in a list, or in `Scope.forkAll`'s, is rejected then, not when it runs.
- **`Scope.named` names the scope in a JSON thread dump** ([#1052](https://github.com/higher-kinded-j/higher-kinded-j/issues/1052)): the name used to be dropped. `named(null)` now throws `NullPointerException`, where it was accepted.
- **A null success throws, or fails a `Try`** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): `Either.right(null)`, `Try.success(null)` and the Path factories throw `NullPointerException`, and so does an `Either` or `EitherPath` `map` whose function returns null. In `Try.of`, `map`, `ap`, `recover` and `TryPath`, a null result gives a `Failure` holding one. A `VResultPath` fails when it runs.
- **`recover(ma, null)` throws on `EitherMonad`, `TryMonad` and `EitherTMonad`** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): whether or not `ma` failed. A null fallback used to give `Right(null)` or `Success(null)`. `Try.orElseGet` refuses a supplier that returns null, as `Validated.orElseGet` does; `orElse(null)` still hands a null back.
- **The one-argument `toEitherPath` and `toTryPath` on a `FocusPath` throw on a null focus** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): they gave `Right(null)` and `Success(null)`. The message names the form that takes an error. `EitherPath.focus(FocusPath)` throws on a null focus too, naming `focus(path.nullable(), …)`, and `TryPath.focus` gives a `Failure`.
- **`ErrorContext.io` treats a null result as a failure** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): its error mapper sees a `NullPointerException`, where the context held `Right(null)`.
- **A function that returns null fails the computation** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065), [#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): a callable, supplier, `map` function, combiner or recovery function that returns null fails the lazy computation when it runs, and the `NullPointerException` names that function. So `VTask.of(() -> { work(); return null; })` fails, where `run()` handed the null back.
- **A null result fails where a computation becomes a `Try` or an `Either`** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): `runSafe`, `toTryPath`, `asTry`, `Scope.joinSafe` and `EffectBoundary.runSafe` give a `Failure` holding a `NullPointerException`. `joinEither` and `FreePath.attempt` give a `Left`, and `catching` hands it to its mapper.
- **A null value passed to a lazy factory throws** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `VTask.succeed`, `State.pure`, `Reader.constant`, `Writer.value`, `Lazy.now`, `Trampoline.done`, `Free.pure`, `FreeAp.pure`, `VStream.of`, `Context.succeed`, the Path factories such as `Path.ioPure` and `Path.id`, and `of` on their monads throw `NullPointerException`. So do the constructors of `StateTuple`, `Writer`, `Trampoline.Done`, `Free.Pure` and `VStream`'s `Emit` and `Seed`.
- **`StateT`, `ReaderT` and `WriterT` refuse a null value** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `of` on their monads, `WriterT.of` and `WriterT.writer` throw on one. A function given to `ReaderT.reader`, or to `map` or `ap` on their monads, that returns null fails the computation. `ReaderTMonad.of(null)` over `Optional` gave an empty `Optional`.
- **`VTask.run()` and `runAsync()` refuse a null from a hand-written task** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): a `VTask` written as a lambda that returns null throws `NullPointerException` from `run()`, and fails the future from `runAsync()`. `PathOps.firstVTaskSuccess` counts such a null as a failure and tries the next path. `VTaskContext.runOrElse` refuses a null default, and `runOrElseGet` a handler that returns null.
- **An `IOPath`, `Par` and a `Scope` refuse a null from a hand-written `IO` or task** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `IOPath.unsafeRun()` throws `NullPointerException` for one, as does each step that runs it, and `EffectBoundary.embed`. `Par`'s combinators and a `Scope` that needs every subtask fail on such a null, and an accumulating `Scope` records it as an error.
- **A stream refuses a null element** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `VStream.of` throws on one, and `fromList`, `fromIterator`, `fromStream` and `generate` fail the stream when they pull one. `fromPublisher` cancels its subscription and fails the stream. `StreamPath` does the same for its sources. `PathOps.traverseVStream` still hands a null item in its list to the function.
- **A `CompletableFuturePath` fails on a future that completes with null** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078), [#1072](https://github.com/higher-kinded-j/higher-kinded-j/issues/1072)): `Path.future` and `fromFuture` check the value as it arrives: map a `runAsync` future to `Unit` first. Cancelling either future cancels both. `withTimeout` and `completeOnTimeout` complete only the new path's future, and the latter refuses a null default. `CompletableFutureMonad` keeps the JDK's null.
- **An `IdPath` always holds a value** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `Path.id(null)` throws, as does `Path.idPath` given an `Id` holding null. `FocusPath.toIdPath` throws on a null focus, naming `toMaybePath`, and so does `IdPath.focus`, naming `focus(path.nullable())`. `Id` and `IdMonad` still hold a null, since every optic's `modify` runs through them.
- **The lazy Paths' `focus` refuses a null focus** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): `IOPath`, `VTaskPath` and `VStreamPath` fail when they run, and the message names the `path.nullable()` form to use. They used to hold the null.
- **`Context.ask` fails on a key bound to null** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): read a key that may hold null with `asks`. `SecurityContext.requireAuthenticated` still fails an anonymous user with `UnauthenticatedException`.
- **A null in a saga fails its step** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065), [#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): a step whose task returns null fails like any other step, and so does a `map` that returns null. The steps before it are compensated, under `Saga.run` and `Saga.runSafe` alike. A null result gave `Right(null)` from `runSafe`, and `run` handed it back.
- **`raiseError(null)` throws on `Maybe`, `Optional`, `MaybeT` and `OptionalT`** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): it gave `Nothing` or an empty `Optional`. Pass `Unit.INSTANCE`. Every `MonadError` now refuses a null error.
- **A null error throws** ([#1077](https://github.com/higher-kinded-j/higher-kinded-j/issues/1077)): `Either.left(null)`, `EitherT.left`, `raiseError(null)` on `EitherMonad` and `EitherTMonad`, and a `mapLeft` or `bimap` whose error function returns null throw `NullPointerException`, where they built `Left(null)`.
- **The conversions into an `Either` check their error even when it is not needed** ([#1077](https://github.com/higher-kinded-j/higher-kinded-j/issues/1077)): `Maybe.toEither` checks its error, or its supplier, even on a `Just`. The optics helpers `getEither`, `getValidated`, `modifyEither` and `modifyValidated` check theirs even when the focus is there. `Try.toEither` throws `NullPointerException` for a mapper that returns null, where it threw `KindUnwrapException`.

#### Spring {#runtime-spring}

- **The declarative HTTP client refuses an empty body for `EitherPath` and `VTaskPath`** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): it gave `Right(null)`. It now throws an `EmptyResponseBodyException`, or fails the task, after the request has been made. A retry policy that retries every throwable would send it again, so exclude that type. Declare `Unit` where the endpoint sends no body.
- **A `Unit` success writes no body** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065)): a handler that writes one value wrote `Unit` as the JSON string `"INSTANCE"`. It now sends the resolved status with no body, as a `void` controller method does.
- **A lazy Path whose step returns null writes the failure status** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): an `IOPath`, `VTaskPath`, `CompletableFuturePath` or `FreePath` handler wrote `null` as the body. The step now fails, as a null does in any lazy computation.
- **A JSON `Either` holding `"right": null` or `"left": null` is refused** ([#1065](https://github.com/higher-kinded-j/higher-kinded-j/issues/1065), [#1077](https://github.com/higher-kinded-j/higher-kinded-j/issues/1077)): `EitherDeserializer` reports it as bad input, as `ValidatedDeserializer` does for a null value.
- **An SSE frame holding `null` fails the stream** ([#1078](https://github.com/higher-kinded-j/higher-kinded-j/issues/1078)): a stream from `HkjClientExchange.vstream` fails with `SseStreamException`, as for any other frame it cannot read.

#### Testing {#runtime-testing}

- **`assertLensLaws` checks set-set in both orders** ([#1169](https://github.com/higher-kinded-j/higher-kinded-j/issues/1169)). A fixture that broke set-set only in the untested order now fails. A lawful lens still passes with the values either way round.
- **`assertAffineLaws` checks set-set on the present target in both orders** ([#1175](https://github.com/higher-kinded-j/higher-kinded-j/issues/1175)). The stricter harness now rejects a fixture that broke set-set only in the untested order. A lawful affine still passes with the values either way round.
- **Lens and affine law harnesses accept one value equal to the current focus** ([#812](https://github.com/higher-kinded-j/higher-kinded-j/issues/812)). Existing lawful fixtures still pass; equal supplied values remain rejected. A setter that ignores updates still fails set-get on the other value.
- **`assertAffineLaws` no longer requires `set` to leave an absent target alone** ([#1023](https://github.com/higher-kinded-j/higher-kinded-j/pull/1023)): a test that relied on it to catch an affine writing there now passes. Add `AffineLaws.assertSetNoOpWhenAbsent(affine, absentSource, value)` to keep that check.
