# Compiler Messages generator

`hkj-book/src/mapping/compiler_errors.md` is generated by this directory. So is its snippet
fixture, `hkj-examples/src/test/resources/fixtures/mapping_compiler_errors.java`. Edit the data
here and rerun the script. Do not edit the page itself: the next run would overwrite the edit.

## Run it

From the repository root:

```bash
./gradlew :hkj-examples:bookMessagesClasspath   # writes hkj-examples/build/book-messages/*.txt
python3 hkj-book/tools/compiler-messages/build_messages.py
```

The script compiles every entry's reproducer with `javac`. It uses the same classpath and processor
path as the book gate. It captures the message the processor really prints and renders the page
from it. If a reproducer stops producing its message, the script prints the compiler output and
fails without writing anything. It needs Python 3 and a JDK 25 `javac` on the `PATH`.

Run it once before you change anything. It should reproduce the committed page exactly, so any
diff you see afterwards is yours.

## Add an entry

Each entry is a `dict` in `GROUPS` in `messages.py`. It needs a matching line in `SHORT`, the
triage table's "what it means" column, in `build_messages.py`.

| Field | What it holds |
|---|---|
| `id` | The entry's anchor on the page. Never change it, because other pages link to it. |
| `heading` | The message with its names replaced: `X` and `Y` for types, `x` and `y` for components or methods, `T` for a type argument, `p` for a package. |
| `fragment` | Distinctive words from the message. They must appear in `heading`, and the triage table shows them. |
| `marker` | Optional. The verify fragment, when it differs from `fragment`. The gate holds the page to it, so it must stay in the real message. |
| `display` | Optional. The triage table's text, when `fragment` alone reads badly. |
| `meaning`, `fix` | One sentence each. The fix is code or an imperative. |
| `rule` | `(link text, target)`: the rule's single home, usually on `rules.md`. |
| `code` | The smallest declaration that provokes the message. It is compiled in package `com.example`, with the shared imports and types at the top of `messages.py`. |
| `kind` | `"note"` for a note rather than an error. The entry is then held by `verify:reports`. |

After the script runs, `./gradlew :hkj-examples:bookVerify` holds every entry to its message on each
build. A processor change that rewords a message fails that gate until the entry is regenerated.

## Which messages belong here

The page catalogues the refusals a reader is most likely to meet, not every refusal the processor
has. When a feature adds a refusal that readers will commonly meet, add its entry in the same
pull request, and put the rule it enforces on `rules.md`. The chapter's rules for where each kind
of rule lives are in [`docs/MAPPING-CHAPTER-GUIDE.md`](../../../docs/MAPPING-CHAPTER-GUIDE.md).
